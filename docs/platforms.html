Platforms

Developed and used on macOS. Linux and Windows are described from reading the code; nothing here claims a test run that did not happen. The pure-logic tests are written to run on all three systems, but no test can show the layout in a live Herdr window. A continuous-integration definition for all three systems is kept in the repository (scripts/ci.workflow.yml), but no run of it has been reported yet, so "Expected to work" below means exactly that.

Notes

  • The nvim socket lives in /tmp on purpose: unix-socket paths are limited to about 104 bytes, and the per-user temporary folder on macOS plus a long home path can exceed that.
  • nvim is started through your login shell so that it finds the same PATH as your terminals. The PATH is read once with printenv PATH, which works in bash, zsh and fish.
  • Paths shown with ~ use Herdr's home(), so Linux and Windows home folders shorten too.
  • The system title bar stays: the layouts do not set "titlebar": "none". portrait-tabs draws minimise, maximise and close buttons only when Herdr says the system draws none (window().buttons), so on Linux and Windows those buttons are not shown with these layouts. Hiding the system title bar is a design choice left to you.
  • A busy folder is not re-read more often than every 1.5 seconds (at most three folders are watched at once; the 10-second timer covers the rest).
  • Key names use Herdr's spelling. ctrl-alt- combinations are avoided because Windows treats them as AltGr.
