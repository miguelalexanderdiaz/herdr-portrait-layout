Install

Two ways: ask an agent, or copy the files yourself. Either way nothing in your existing layouts, mods or keys is overwritten.

With an agent

In a terminal agent inside Herdr (or any agent that can edit your Herdr home folder), say:

install https://github.com/miguelalexanderdiaz/herdr-portrait-layout

A good agent will (this is the protocol Herdr's own reference gives for layouts other people made):

  1. Read RECIPE.md, AGENTS.md and every file before writing anything, and tell you that the mods run programs and read folders (the short list is on Privacy) and use no network.
  2. Copy the layout files into layouts/ and each mod folder into mods/, leaving the recipe and the preview out. If a name is taken it renames the new one, including the mod names inside the layouts and the mods/<name>/ asset paths.
  3. Merge keys.json into yours and ask before replacing a key you already use.
  4. Run herdr-app check on each mod, then switch to the layout. Your own layout stays as it was.

The step-by-step version for agents is For agents and AGENTS.md.

By hand

You need a clone of the repository and the path of your Herdr home folder. herdr-app --help prints it on its last line. Herdr's reference gives ~/.config/herdr-app as the default, the same on macOS and Linux; HERDR_APP_HOME overrides it. On Windows the default is not confirmed here, so use what herdr-app --help prints.

macOS and Linux

To try it without touching your own setup, run it in a scratch Herdr home first (HERDR_APP_HOME=<empty folder>).

git clone https://github.com/miguelalexanderdiaz/herdr-portrait-layout.git
cd herdr-portrait-layout

# The Herdr home folder (herdr-app --help prints it on the last line).
H="${HERDR_APP_HOME:-$HOME/.config/herdr-app}"
mkdir -p "$H/layouts" "$H/mods"

# Never overwrite: anything that already exists is reported and skipped.
# Includes the layouts' .svg thumbnails. Rename a layout together with its "preview" field.
for f in layouts/*; do
  if [ -e "$H/$f" ]; then echo "exists, rename first: $f"; else cp "$f" "$H/layouts/"; fi
done
for m in mods/*; do
  n="${m#mods/}"
  if [ -e "$H/mods/$n" ]; then echo "exists, skip or rename: $n"; else cp -R "$m" "$H/mods/$n"; fi
done

for m in mods/*; do herdr-app check "$H/mods/${m#mods/}"; done   # check every mod you now have
herdr-app do layout.switch --name portrait                          # switch to the layout

Windows (PowerShell)

git clone https://github.com/miguelalexanderdiaz/herdr-portrait-layout.git
cd herdr-portrait-layout

# The Herdr home folder. If herdr-app --help prints another folder, set $H to it.
$H = if ($env:HERDR_APP_HOME) { $env:HERDR_APP_HOME } else { Join-Path $HOME ".config\herdr-app" }
New-Item -ItemType Directory -Force "$H\layouts", "$H\mods" | Out-Null

foreach ($f in Get-ChildItem layouts) {
  if (Test-Path "$H\layouts\$($f.Name)") { "exists, rename first: $($f.Name)" }
  else { Copy-Item $f.FullName "$H\layouts\" }
}
foreach ($m in Get-ChildItem mods -Directory) {
  if (Test-Path "$H\mods\$($m.Name)") { "exists, skip or rename: $($m.Name)" }
  else { Copy-Item $m.FullName "$H\mods\$($m.Name)" -Recurse }
}

foreach ($m in Get-ChildItem mods -Directory) { herdr-app check "$H\mods\$($m.Name)" }
herdr-app do layout.switch --name portrait

What was run: the macOS and Linux script, in a scratch Herdr home on macOS (nothing overwritten, herdr-app check passed for all seven mods). The PowerShell version follows the PowerShell documentation and has not been run on a Windows machine; the default home folder in its first lines is a guess, so use the path herdr-app --help prints if it differs.

Keys

Open the repository's keys.json and add its sections and keys to the keys.json in your Herdr home folder. If you have no keys.json yet, copying the file is enough. If a key is already used by something of yours, keep yours and pick another for ours. If Herdr rejects the file it writes the reason to keys.error and keeps the last good version. The table is on Configuration.

If a name is taken

Rename the new thing, never the old one. For a layout, rename the file and its .svg thumbnail, change the preview field in the layout's root to the new thumbnail name, and rename the section layout:<name> in your keys and the layout.switch:<name> values that point at it. For a mod, rename its folder and every mods/<name>/ path inside it, then the mod name in the layouts. The constant PICKER at the top of bar-strip/main.js holds the name of the bundled attention-picker. Details: For agents.

If you already have attention-picker from the herdr-agents-waiting repository, keep yours and skip the bundled copy.

Optional: the Vault panel

The layouts do not carry a Vault panel, so they work without the Obsidian mods. To add it, install the vault and vault-reader mods from herdr-obsidian-vault, then insert the contents of snippets/vault-panel.json into the children of the stack with id panel-body in each layout file you use. The Vault button in the strip and the note rows in the tree appear when both are there: the mod installed and the panel in the layout. Ids that mods look up and that must stay as they are: panel, panel-body, files, changes and vault; bar is named only by the toggle key.

Check it worked

  • Every herdr-app check line ends without an error.
  • After the switch the window shows the strip with Search, Add machine and Settings, and the tab bar under it.
  • If something is off, Herdr writes why to layout.error in its home folder and keeps your last good layout. ctrl-alt-shift-escape always puts the default layout back.

Uninstall

  1. Switch to another layout (ctrl-shift-l cycles layouts, or use Settings).
  2. Delete from your Herdr home folder: layouts/portrait.json, layouts/portrait-bottom.json and their .svg thumbnails, and the mod folders bar-strip, portrait-tree, portrait-tabs, portrait-pane, portrait-files, nvim-float (and attention-picker only if it came from this repo).
  3. Remove the keys you merged from keys.json.
  4. Delete the folder data/portrait-tree-spines/ in the Herdr home folder (the only file this layout writes there).
  5. Any /tmp/herdr-nvim-*.sock files from nvim sessions disappear when nvim exits or on reboot; delete them if one is left.
